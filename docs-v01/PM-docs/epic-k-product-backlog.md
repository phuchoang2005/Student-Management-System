# Epic K — Performance Remediation

Project Management — v0.1 addendum to [`docs-v00/PM-docs/01-product-backlog.md`](../../docs-v00/PM-docs/01-product-backlog.md). Same 5-column format Epic J (`PM-029`–`PM-039`) uses: `ID | Item | Priority | Estimate | Source`. Priority is MoSCoW, estimates are ideal solo-developer hours — neither field is new, both are the existing backlog's own convention.

Epic K turns `docs-v01/Benchmark/08-hazard-fix-specs.md`'s ten still-open `IP-*` items into scheduled work. **`IP-09` (keep actuator/Micrometer permanently wired) is excluded** — it is already implemented and exceeded (permanent `pom.xml` dependencies, profile-gated `:8081` management port, `SecurityConfig` matcher, and a six-dashboard Grafana/Prometheus stack per `docs-v00/Benchmark/benchmark-strategy/06-dashboard-building.md`), so there is no work left to schedule. See `docs-v01/Benchmark/08-hazard-fix-specs.md`'s corrected `IP-09` entry for the evidence.

**Epic K subtotal: 47h** (41h counting only `PM-040`–`PM-048`, since `PM-049` is deliberately unscheduled — see `epic-k-sprint-plan.md`).

The item order is the roadmap's phase order, not backlog-entry order: `PM-040`–`PM-042` are configuration/tooling with no application-code risk, `PM-043`–`PM-045` share the same three search repositories and are ordered cheapest-first within that group, `PM-046` is an independent module portable from an already-proven pattern, and `PM-047`–`PM-048` bound failure modes rather than reduce latency. `PM-047` is Must despite carrying `06`'s P1 severity label, for the same reason `docs-v01/Benchmark/07-improvement-roadmap.md` gives: it targets the one confirmed defect in the whole benchmark set (silently lost audit-trail data under a realistic burst), and a severity label assigned by impact-vs-cost is not the same axis as urgency. `PM-045` carries this epic's largest estimate and a Should rather than a Must specifically because it is gated on a product decision this backlog cannot make on its own — see `docs-v01/BA-docs/non-functional-requirements.md` §3.1 for the one data point available toward that decision, and `docs-v01/SA-docs/07-benchmark-remediation-impact.md` §2 for its API-contract consequence.
