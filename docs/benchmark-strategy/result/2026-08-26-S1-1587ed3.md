## Findings

- **F1 — Protocol changed mid-sprint, before any run was accepted.** The original 60 s warm-up / 300 s steady-state / 3-repetition protocol was estimated at ~13 h to run once across S1→S2→S3, which is impractical to actually exercise repeatedly. `02-benchmark-plan.md` §2 was revised to ~15 s warm-up / 30 s steady state / 1 repetition at your direction. This run uses the revised protocol. Consequence: no median-of-3 noise protection, and a much smaller sample count per scenario (30 s vs 300 s) — p99 in particular should be read as indicative, not exact.
- **F2 — Every scenario breached its SLO, including by-key controls.** `02-benchmark-plan.md` §3 step 1 expected S1 to "pass everything comfortably." It did not, including BM-STU-005/BM-BK-004/BM-ENR-004/BM-ME-001 — unique-index lookups that should be flat regardless of hazard. The leading explanation is **not** a per-endpoint regression but two confounds specific to this fast/shared-host setup: (a) the SLOs (`01-benchmark-strategy.md` §4.2, e.g. Read-single ≤50ms p95) were calibrated with the original heavier protocol on a properly-warmed JVM in mind, never validated against a 15s/30s window; (b) 20 VUs against Hikari's default 10-connection pool plausibly queues *every* request regardless of hazard, on a 4-core host that's also running MySQL and the k6 driver itself (`01-benchmark-strategy.md` §7.1's parity caveat, sharper here than usual). This run is recorded as-is rather than re-tuned, per the "record the failures too" convention in `result/README.md`. **The SLO numbers in this record should not be read as hazard findings without a follow-up run that isolates the pool-contention confound** (that isolation is what `BM-XC-003`, Sprint 8, is for).
- **F3 — Host CPU was not captured.** `01-benchmark-strategy.md` §7.2 calls for recording host CPU during the run so a k6-saturated run can be discarded rather than reported; this pass skipped that instrumentation in the interest of speed. Not repeated for S2/S3 either — a gap in all three records, not just this one.
